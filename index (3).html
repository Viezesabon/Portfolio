FORENSISCH RAPPORT

Volledig forensisch rapport van het BYB-beveiligingsincident. Vier sporenbronnen gecorreleerd tot een complete aanvalstijdlijn. Conclusies gedocumenteerd voor opdrachtgever met zekerheden, hypothesen en beperkingen.

FORENSISCH RAPPORTCHAIN OF CUSTODY CORRELATIEDATA EXFILTRATIE TIJDLIJNINCIDENT RESPONSE
SCOPE VAN HET ONDERZOEK

Op verzoek van de directie van BYB is forensisch onderzoek gestart naar aanleiding van een beveiligingsincident op 23-11-2025. Onderzoeksobjecten: memory dump (janemem.mem, 2GB), disk image (janedisk.img, 26.8GB, ext4, GPT), netwerkopname (janenet.pcap, 39MB) en malware sample (update-tool, ELF 64-bit). Alle hashes SHA256/MD5 geverifieerd en vastgelegd. Disk image uitsluitend read-only gemount.

GECORRELEERDE BEVINDINGEN
INFECTIEVECTOR
Jane ontving een gerichte spearphishing mail "UpgradeTool". Om 00:10:33 CET geopend via Gmail. Link leidde naar phishing landing page op Microsoft Azure IP 20.157.119.19.
MALWARE DOWNLOAD
00:11:45 CET: download van update-tool via welcome.html. Opgeslagen in /home/jane/Downloads/update-tool. Bevestigd via disk image Firefox history en PCAP GET-request.
DATA EXFILTRATIE
00:12:28 CET: HTTP POST van 7947 bytes XOR-versleutelde data naar /processm.php. Gedecrypt met key "JustForFun". Resultaat: Gmail en Instagram credentials van Jane gestolen.
SCOPE BEPERKT
Alleen Jane's werkstation 192.168.68.116 betrokken. Geen lateral movement naar andere systemen. Incident geïsoleerd tot één werkstation. 100% van externe communicatie afkomstig van dit IP.
CONCLUSIES EN ZEKERHEDEN

Met hoge zekerheid vastgesteld op basis van correlatie tussen vier sporenbronnen: update-tool is een credential stealer (infostealer) die SQLite gebruikt voor lokale data uit browserpassword managers, wget inzet voor exfiltratie (Living off the Land), en XOR-encryptie met hardcoded sleutel. IP 20.157.119.19 aangetroffen in disk image, malware binary én PCAP. Tijdlijnen uit alle drie bronnen komen exact overeen na conversie CET/EST.

BEPERKINGEN

De update-tool variant in het geheugen komt niet exact overeen met het bestand op de disk image, mogelijk twee varianten gebruikt. Het bestand C2_push.txt kon niet worden gereconstrueerd (snel verwijderd na aanmaak). De exacte inhoud van de phishing mail is niet volledig gereconstrueerd, alleen de titel en URL zijn bekend. Of Chrome credentials daadwerkelijk zijn buitgemaakt blijft onzeker, SQLite strings wijzen erop maar bewijs ontbreekt.

MIJN ROL

Youssef: inleiding & context, volledige DFD inclusief trust boundaries, STRIDE-dreigingsanalyse. Vincent: risicoanalyse, countermeasures, afweging en eindadvies. Door deze taakverdeling sloten de STRIDE-dreigingen direct aan op de risicotabel.

Tijdens het werken liep ik tegen feedback aan dat de eerste DFD-versie niet duidelijk genoeg was. Actoren als beheerder en cloudbeheerder ontbraken, en authenticatie/autorisatie waren onvoldoende uitgewerkt. Ik heb dit aangepast, processen hernoemd en trust boundaries duidelijker gemaakt.

DFD — WAT IK HEB OPGESTELD

7 processen (P1-P7), 3 datastores (D1-D3), 4 externe entiteiten. Drie trust boundaries gedefinieerd:

// TRUST BOUNDARIES
TB1: Gebruiker/Beheerder <-> GlowLock systeem  > inloggegevens, sessietokens, ontgrendelverzoeken
TB2: GlowLock systeem <-> GlowLock Cloud  > lograpporten
TB3: GlowLock Cloud <-> Cloudbeheerder  > cloudloggegevens inzien en beheren

De DFD beschrijft de volledige gebruikersflow: inloggen → sessietoken ontvangen → ontgrendelverzoek → RF-commando naar slot → toegangsstatus → logging lokaal en cloud. Elke stap is een apart proces met zijn eigen kwetsbaarheden.

STRIDE-ANALYSE — WAT IK HEB UITGEVOERD

Per proces, datastore en kritieke dataflow systematisch alle zes STRIDE-categorieën doorlopen. Focus op onderdelen met gevoelige data: authenticatie, autorisatie, toegangsbeheer en logging.

WAT IK HEB GEBOUWD: LIVE KAARTCOMPONENT

De kaartcomponent toont realtime de locatie van de gebruiker en zijn matches op een interactieve kaart. Ik heb dit gebouwd met de Expo Location API voor GPS-data en H2 als database voor de opslag. De kaart is vergrendeld achter een locatie-deelscherm.

De gebruiker heeft geen keuze over hoe lang of hoe vaak de locatie wordt gedeeld. Geen pauzeknop, geen tijdslimiet. Continue surveillance als standaard, niet als keuze. Dit is een bewust geimplementeerd dark pattern — en dat was de opdracht.

ETHISCHE ANALYSE

Naast het bouwen heb ik een ethische analyse geschreven van Linder op basis van de AVG en de Digital Services Act. Linder verzamelt structureel meer data dan nodig. Account verwijderen is bewust moeilijk gemaakt — verboden door de DSA. Studenten met minder data krijgen slechtere matches. Het systeem straft privacy. Dat was de boodschap.
